# 知识库说明

> 适用项目：xuanchen-monolithic（萱晨单体项目）
> 相关模块：`BackEnd/xuanchen-springboot3/xuanchen-ai`（LangChain4j 1.20.2 + 本地 Ollama + pgvector）
> 本文说明知识库当前支持解析的文件格式、判定链路与已知限制，供开发、测试与运维对照使用。

---

## 一、解析链路

文档从进入知识库到可被检索，需依次通过四道关卡：

```
上传/导入 → ① 文件中心安全校验 → ② 落 MinIO + file_info → ③ Tika 抽正文 → ④ 分块向量化 → pgvector
                              (扩展名白名单 + 魔数)        (ApacheTikaDocumentParser)   (bge-m3 / 1024 维)
```

| 关卡 | 代码位置 | 失败表现 |
|---|---|---|
| ① 扩展名白名单 + 魔数校验 | `filemanage/util/FileMagicUtil.java` | 上传直接拒绝，提示「不支持的文件类型」或「文件内容与扩展名不符」 |
| ② 存储与元数据 | `filemanage/service/impl/FileInfoServiceImpl.java` | 超出 50MB 上限 / 配额不足 |
| ③ Tika 正文抽取 | `ai/kb/rag/AiIngestService.java#parse` | 状态置 `failed`，`error_msg` 记录原因 |
| ④ 向量化落库 | `AiIngestService.java` → `EmbeddingModel` | 状态 `failed`，可重试 |

文档状态机：`pending → parsing → ready / failed`（前端轮询，`parsing` 超 10 分钟视为线程异常中断，允许强制重新入队）。

---

## 二、支持解析的格式（可正常入库）

以下格式在链路 ①③ 均能通过，是当前知识库**真正可用**的输入：

| 扩展名 | MIME 类型 | Tika 解析器 | 抽取内容说明 |
|---|---|---|---|
| `pdf` | application/pdf | PDFBox | 抽取文字层与表格文本；**扫描型 PDF 无文字层则抽不到内容** |
| `doc` | application/msword | POI HWPF（scratchpad） | 正文、表格单元格文本 |
| `docx` | application/vnd.openxmlformats-officedocument.wordprocessingml.document | POI XWPF | 正文、表格、页眉页脚文本 |
| `xls` | application/vnd.ms-excel | POI HSSF | 单元格文本按行列拼接 |
| `xlsx` | application/vnd.openxmlformats-officedocument.spreadsheetml.sheet | POI XSSF | 同上，含多 Sheet |
| `ppt` | application/vnd.ms-powerpoint | POI HSLF | 幻灯片占位符与备注文本 |
| `pptx` | application/vnd.openxmlformats-officedocument.presentationml.presentation | POI XSLF | 同上 |
| `txt` | text/plain | 文本解析器（编码探测） | 原文直接抽取 |
| `md` | text/markdown | 文本解析器 | **按原始 Markdown 文本入库，不做语法渲染或剥离** |
| `csv` | text/csv | 文本解析器 | 逗号分隔原样入库 |
| `json` | application/json | Jackson 文本解析 | 结构化文本入库 |

### 手动录入

`POST /ai/kb/doc/text` 将正文包装为 `<标题>.txt` 复用文件中心字节存储，走同一套校验与解析链路；单次录入上限 **200,000 字符**（`AiDocumentController.TEXT_MAX_CHARS`），超限需拆分分次录入。

---

## 三、可上传但无法解析的格式

以下扩展名在文件中心白名单 `GENERAL_ALLOW` 内，**能成功上传、但 Tika 抽不出正文**，最终落 `failed`：

| 类别 | 扩展名 | 失败原因 |
|---|---|---|
| 图片 | `jpg` `jpeg` `png` `gif` `webp` `bmp` | 依赖中未引入 Tesseract OCR，无文字层可抽 |
| 矢量图 | `svg` | 二进制/XML 容器语义，不作为知识来源 |
| 压缩包 | `zip` `rar` `7z` | 容器格式，不作为可用能力 |
| CAD | `dwg` | Tika 无 CAD 解析器 |
| CAD | `dxf` | Tika 无 DXF 解析器（ASCII 但无对应 parser） |

典型报错：`未解析出任何文本内容（可能是纯图片扫描件）`。

前端「从文件中心导入」通过 `FilePicker.vue` 的 `UNPARSABLE_EXTS` 黑名单预先禁选图片/压缩包/音视频/安装包类文件，但**未包含 `dwg`、`dxf`**——这是当前唯一的收口缺口。

---

## 四、完全不允许上传的格式

不在 `GENERAL_ALLOW` 白名单内，上传阶段即被拒绝（知识库与文件中心共用同一份白名单，知识库不单独放行）：

```
html  htm  xml  eml  msg  epub  odt  rtf  wav  mp3  mp4  avi  mov
exe  dll  msi  apk  iso  bin  sh  bat  py  java  php  js
```

其中 `html / xml / epub / rtf / odt` 本身是 Tika 可解析的格式，被拦在**白名单**而非解析能力上；若需要支持，在 `FileMagicUtil.GENERAL_ALLOW` 与 `detectExtSet` 同步放行即可。

## 五、当前检索配置

| 配置项 | 默认值 | 位置 | 说明 |
|---|---|---|---|
| Embedding 模型 | `bge-m3` | `application-ai.yml`（`AI_EMBED_MODEL` 可覆盖） | 中文/中英混合召回优；更换模型需全量重新向量化 |
| 向量维度 | `1024` | `application-ai.yml` `vector.dimension` | 与 bge-m3 绑定，改维度需重建 `ai_chunk` 列与索引 |
| 分块大小 / 重叠 | `500` / `50` | `rag.chunk-size` / `chunk-overlap` | `DocumentSplitters.recursive`，段落+句子边界，中文友好；可在知识库级覆写（`ai_kb` 表列） |
| 召回数量 | `5` | `rag.max-results` | 单次检索返回分块数 |
| 相似度阈值 | `0.6` | `rag.min-score` | 换模型需重新标定 |
| 向量库 | 独立 PostgreSQL + pgvector | 库 `xuanchen-kb`，表 `ai_chunk` | 首次启动自动建表，前提是已 `CREATE EXTENSION vector` |
| 元数据过滤 | `kb_id` / `doc_id` / `file_name` | `AiIngestService#parse` | 分块自动继承，用于检索过滤与引用溯源 |

说明：链路为**纯稠密向量检索**（cosine），bge-m3 原生的 sparse / ColBERT 混合召回能力当前未启用。

## 六、约束与注意

- **全本地推理**：数据不出内网，Ollama 地址由 `AI_OLLAMA_URL` 注入；本地 CPU 推理较慢，对话超时放宽至 300 秒。
- **重复解析**：`POST /ai/kb/doc/parse` 会先按 `doc_id` 清掉旧向量再重新入库，可用于失败重试与调参后重建。
- **内容查重**：同一知识库内按 MD5 拦截重复上传/导入；`failed` 文档放行（视为未入柜，允许重传修复）；跨知识库不去重。
- **删除语义**：删除文档时逻辑删除记录并清理其全部向量，MinIO 原始文件保留在文件中心。
- **版本对齐**：Tika 3.x 依赖 commons-io 2.16+，根 pom 已全局钉版，避免 `xuanchen-online` 的 2.15.0 就近顶掉导致 `NoClassDefFoundError`。
